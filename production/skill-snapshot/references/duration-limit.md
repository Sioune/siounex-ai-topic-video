# 时长预算与硬验收

## 不得突破的总长
所有此类短视频完整导出总时长必须 ≤60秒，包含高光、音乐开场、所有过渡、正文和已绑定独立片尾（当前v5实际119帧/30fps，保守预留4秒）。不是“正文60秒”，不是“约一分钟”，也不因编码、模板或旧例放宽。66.6秒成片不合格。保留原规则、旧文件和历史验证记录，但旧版超时不成为新片许可。

## 先预算，再实测
1. 记录最终时间轴的开头、正文、过渡、片尾区间。正文可用时间＝60秒－已绑定片尾的实际占时（当前v5为119/30秒）－其余非正文实际占时。重叠只按最终时间轴真实重叠扣除一次，不把计划淡化或口头重叠算成节省。采用4秒保守片尾预算时，单独3秒音乐开场与片尾且无其他独立占时时，正文最多53秒；若另有独立过渡则继续扣。
2. 按预算精简重复铺垫、旁枝或信息量，保留核心故事、事实限定与兑现钩子的画面。必要时仅对旁白适度保音高变速，重对齐字幕、口型和镜头；实际听审确保自然清楚，不为了凑时长无限提速。音乐与原片尾不随正文倍速。
3. 字数/语速估算仅用于写稿；配音生成后以真实音轨时长重新核预算。高光前置、改稿、转场或片尾拼接后再检查。可留小量工程余量防音视频封装尾部超出，但硬上限始终60秒。
4. 不用粗暴 `-t 60`、机械截句、截尾字、删音频结尾或压缩原片尾“修合格”。先改内容/时轴并重新导出，实际听完末句及片尾，确认语义和声音完整。

## 最终文件硬检查
- 运行 `python scripts/qa_duration.py 最终成片.mp4`；`qa_media.py` 已集成同一规则。脚本读取实际文件的ffprobe容器时长和音视频流时长/起点，取保守最大播放终点；缺失、无效或任一有效值 >60 即失败。`qa_media.py --duration-tolerance` 只用于与预期时长比较，不得放宽60秒上限。
- 对实际交付同一文件保存检查输出、文件身份和哈希；任何重新导出都重新检查。缺ffprobe/检查失败不能标通过。完整解码与真实末句听审仍须分别做，时长通过不等于叙事完整。
- 超时结果留作待修版本，不可标“合格成片/可发布”。先说明真实超时，再删内容或适度调速、重排预算、重新导出复测。待修文件可用于说明问题，不能把它当满足任务的最终交付。
- 自测：`python scripts/qa_duration.py --self-test`；另以真实导出样本验证60秒边界和66.6秒退回。测试素材不是用户视频，不代表实际项目已修好。


## 当前v5的实际边界

当前两版视频均119帧/30fps，视频及容器实测3.966667秒、完整AAC音轨3.95秒；4秒仅为保守制作预算，不是要求补帧或截断原件。总长仍以实际完整成片的容器、视频和音频终点硬检，不能用119帧推定音轨已听审。旧冻结工程继续按原真实帧数、时长与哈希恢复，不将本次升级写成旧文件的新核验。
