# 目录与本地开发

## 三处工作区

| 位置 | 用途 |
| --- | --- |
| 本 GitHub 快照 | V328 源码和脱敏进展交接，可独立审阅与继续开发 |
| 原 Sites 正式源码 | 当前正式发布来源；不能用本快照覆盖并行开发的更新 |
| 本机制作运行端 | 原计划任务实际加载的脚本及私有业务文件；与云端部署不自动同步 |

## 技术与目录

React 19、TypeScript、Vinext/Vite，Sites Worker + D1 + 私有 R2。Node.js 要求 >=22.13.0。

- `app/`、`components/`：网页与接口。
- `lib/`：任务、审核、发布、归档和制作契约。
- `scripts/`：构建、验证及本机制作执行脚本。
- `production/`：制作规则、模板、片尾和品牌资源、运行手册。
- `tests/`：定向及历史回归测试。
- `drizzle/`、`db/`：数据库结构与迁移。
- `build/`、`vendor/`：构建插件与依赖适配源码，不能按输出目录排除。
- `.openai/hosting.json`：原 Sites 项目标识及 D1/R2/MCP 配置，无秘密值。

## 本地开发入口

在隔离开发目录使用：

```sh
npm run install:ci
npm run dev
npm run build
```

安装/构建的 portable 与 managed-linux 选择、私有登录、D1/R2 绑定及本地迁移细节见 [原 starter 说明](STARTER-README.md)。不能仅凭页面外壳打开就判断生产数据、登录或制作链路正常。

`npm test` 运行项目测试；先选择受改动影响的组。本包未重新执行类型、构建或全库测试，历史基线失败和需要现场材料的测试仍须按原记录解读。

Sites 发布必须沿正规 Sites 工具及当前技能操作，并保留本人私有受众。不要在没有最新状态、凭据和权限核验时运行制作脚本、重建计划、直接操作发布平台或回放旧生产命令。
