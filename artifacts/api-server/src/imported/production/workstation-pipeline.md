# 制作工位与接续

同一个既有 Windows 制作任务负责一次有限执行轮，不新增第二个轮询或后台进程。轮内最多扫描十六次候选，领取动作顺序进行，排除在途任务；排队者不挤占其他空闲工位的接纳机会。五个工位最多实际同时加工五条片。同一任务只有一个活动阶段，同一工位容量为一，等待工位时不持有上游工位。

| 工位 | 工作 | 完成后交接 |
| --- | --- | --- |
| preparation | 文字、审核执行与素材准备 | 当前版本文字／素材回执 |
| voice | 普通配音或已授权本人声音获取、原请求对账 | 完整音轨及其绑定 |
| render | 音画字幕同步、本地渲染与工程打包 | 成片、工程与制作回执 |
| assets | 双封面、平台文案材料及发布包组装 | 版本绑定的完整候选材料 |
| archive | 上传、全量读回核验及站内接收 | 确认的归档与待审状态 |

不同工位可同时加工不同片子。例如一条片在配音工位等待结果时，另一条可在渲染工位合成，第三条可在归档工位上传。归档内部沿用六路固定分片传输，这是该工位的传输实现，不额外提高工位容量。

每个阶段继续使用既有任务、请求、版本、SHA、租约与幂等回执。取得工位后才写入该阶段开始记录；等待预算不足时保留已完成阶段，下个自然轮从同一断点接续。未知的媒体调用仍先对账，不能因为释放工位重新配音或播放。普通版与本人声音版各自的人审、模板交替及早浅晚深类别 FIFO 不变。

每轮写入 `workstation-events`，记录工位、任务和起止时刻；最终 `workstations` 快照保存各工位最大占用数和实际跨工位重叠。代码支持并行与自然轮实际出现重叠应分别验证，不以缩短检查周期或四平台发布并行代替制作验证。

每次排队、开始、完成或失败同时原子更新本轮 `workstation-current.json`，只保留已验证的工位占用与等待数。原定时执行器的心跳读取此快照，制作台可直接显示哪些工位被占用、多少任务排队；排队不记为已开始，工位持有到实际操作完成，不因心跳或等待时间擅自释放。独立观察写入失败不打断制作，原不可变事件仍保留。

原计划任务按每3分钟检查登记。已开始的制作自然完成，可能跨过多次触发；结束回执按本轮开始时刻的原周期计算结束之后的下次检查，服务器依据真实结束时刻验证该时间。不得把已过去的首次触发填为未来检查，也不得因长轮结束回执被拒绝而残留“正在制作”的旧状态。此处只登记现有计划，不创建或修改计划任务。

关键词研究仍沿用独立研究执行入口及既有有限预算。本模块仅调度制作任务；发布轮询、平台提交和手机操作由原有对话负责。
