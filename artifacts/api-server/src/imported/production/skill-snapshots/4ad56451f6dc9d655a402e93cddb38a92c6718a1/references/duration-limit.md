# 时长预算与硬验收

## 当前规则（2026-10-22本人最新授权）
最终完整导出仍必须≤60秒，含高光、音乐开场、全部过渡、正文及原v5片尾119帧／30fps（3.966667秒，AAC原声3.95秒）。这不是允许把70秒当成合格成片；70秒是决定待修版本能否直接调速的阈值。旧已发布、已审冻结包和历史回执保留原身份，不为新规则重做或重发。

以**当前完整实测正文音轨及所绑定原片尾的整片实际时轴T**分类；非正文固定占时也计入，真实重叠只算一次：

- T≤60秒：保留现有速度，不因本规则额外加速。
- 60<T≤70秒（超出不超过10秒，70秒含边界）：不额外缩稿，正常制作队列复用完整原音轨，仅对正文口播保音高额外提速，使完整导出≤60秒。已有处理速度、额外速度及累计速度须如实记录，累计可超过旧1.25／1.3默认上限；旧上限不能拦住此次明确允许的调速，也不能盲目叠加。
- T>70秒：进入既有缩稿与重新审核流程，不以这一分支自动截句、改写已审稿、无限提速或重录。

T必须来自完整实测音轨／完整准备时轴和实际原片尾，不能只看字数、名义分镜、早期未处理的独立录音或文件名。原音轨已按旧速度处理时，从这份已验证的当前完整音轨计算额外因子，不把原始录音时长冒充当前时长。缺完整测量时保留待核，不猜测分支。

## 预算与额外速度
1. 写稿前仍扣除原片尾和其他固定占时，尽量让普通版一次完成。该新授权解决实测后的10秒内超时，不默认把所有稿件写到70秒。
2. 记正文可调部分B秒、片尾和其余固定占时F秒，T=B+F。60<T≤70时，正文目标≤60−F，额外速度因子至少为 `B / (60−F)`，按实际帧／封装约束取能使最终≤60的值。帧预算按30fps最终至多1800帧，原v5尾119帧不增减；有其他固定占时继续扣除。
3. 例如已有正文1870帧、v5尾119帧，合计1989帧＝66.3秒，属于可直接调速分支；正文需压到至多1681帧，额外因子至少 `1870/1681`。这只是该实测实例，不是其他片固定倍速。
4. 仅正文口播保音高处理，完整保留所有批准文字、断句和尾字，不新增配音调用；按新实测词时间重对齐字幕、数字人口型、章节及镜头切点。实演源片保持正常速度和真实因果，不能对整片视频统一倍速或伪造零延迟。BGM与其他音乐依新时轴重摆，保持原速；原片尾保持1×、全部原帧和完整原声，不叠正文声音。
5. 禁用粗暴 `-t 60`、机械截尾字、删音频结尾、压缩原片尾或补帧来“修合格”。实际听审与手机回看仍须确认自然清楚；没有听过不宣称听过。

## 审核、接续与最终硬检查
- 正常队列接续已有完整音轨和工程；不手工重跑单条媒体，不因实现或规则哈希变化重做其他旧工程。普通配音版首审、本人声音版二审继续保留，调速后的结果仍按原流程审阅；模板认可不代替内容审核。
- 浅深模板继续交替制作，审核后入仓分早晚类别：08:00浅正文＋原v5深尾，18:00深正文＋原v5浅尾，各类别FIFO；提前准备与正式提交复用同一冻结包。
- `python scripts/qa_duration.py 最终成片.mp4` 和集成它的 `qa_media.py` 仍以ffprobe容器及音视频流的保守最大播放终点执行严格≤60检查。任何有效值>60均不合格；`--duration-tolerance`只比对预期时长，不放宽最终上限。报告中的修复建议不代表已经执行调速或完成验收。
- 保存同一最终文件的身份、SHA与检查输出；每次重新导出重新核验。完整解码、末句／原片尾听审与同步检查分别完成，不能用时长通过替代音画验收。
- 自测：`python scripts/qa_duration.py --self-test`。覆盖60秒最终硬边界、70秒调速分类含边界及大于70秒缩稿；合成测试不证明任何用户视频已经修好。
