# 素材先行的前置预稿

## 先找值得看、能真实展示的内容
- 研究优先寻找真实可用的图片、视频或可复现的实际操作画面，同时查清核心事实。先回答“普通观众为什么在意、原来不知道什么、画面能让他立刻看懂什么”，再选叙事角度；不要按新闻报道或产品功能目录写口播。
- 素材不是写完稿后的装饰。先打开并检查候选素材的实际内容、真实分辨率、清晰度、连续动作、关键结果和竖屏可用性，再让这些素材决定可讲的具体故事。横屏素材须先验证完整视角在3:4主区内等比呈现是否能交代全局，再规划随旁白聚焦及回全局；竖屏可用不等于能强行中心裁满，不能牺牲空间、路线或数值关系。文章链接、搜索摘要、缩略图或计划去录制均不等于已获得可剪素材。
- 优先使用与本次故事直接对应的实际演示、真实结果和前后变化；确需录制时先确认访问、账号、工具和授权。不能编造自己实际点过、生成过、测试过的动作，也不能用拟制UI、生成图或其他案例冒充本次实际演示。缺对应素材时收窄说法或标为待补，不为了讲完整而制造证据。
- 将素材状态分清：已获取并检查、已定位但尚未获取/验证、需要实际录制、受授权或访问阻塞。只有前者可写成现成可剪；存在清晰文件链接也不自动证明有复用权利。

## 后台核验，前台讲故事
- 写稿、改稿和审稿前执行 [前台文案门控](narration-gate.md)。后台研究记录与前台口播/字幕/叠字分字段保存；不得把整份研究报告直接作为待朗读正文。
- 必要事实仍须核验，特别是核心能力、实际结果、数字、日期与影响结论的限制。后台记录来源链接、时间、素材入/出点、关键画面、权利/许可和仍未确认的事项；不因追求爽快而省掉核验。
- 不把报道考据、逐条出处、机构头衔或授权说明搬成口播主体；用普通话大白话讲具体问题、反差、行动和真实结果。只在理解核心事实必需时自然说明来源或限制，不制造“人人免费立刻可用”等假印象。
- 不自行添加引用脚注、来源考据角标、审片标记或技术标签来证明做过研究。保留原素材自带的版权/权利标记和获批品牌元素；确有署名/引用要求时在素材许可允许的位置落实，若必须画面署名且与干净画面要求冲突，先说明并换素材或取得用户决定，不删除权利标记。

- 素材不足时继续找、收窄到确有画面的切入点，或把预稿标为素材待补。不得用“据某媒体报道”、朗读文章/发布稿、来源清单或核验免责声明凑满正文，也不得把网页截图当成实际能力演示。

## 从预稿阶段同时设计0–3秒
- 每版预稿都单列开头0–3秒，同时写明口播钩子、真实画面、节奏与声音，回答：观众看见什么、听见什么、为什么愿意继续看。不要只写一句吸引人的台词，再让画面等待加载或凑合配图。
- 第一个画面就给出清晰、有趣、与后文对应的真实核心内容；首帧独立看也应是完整、高清、手机可读的成品构图。避免加载页、缩得看不清的小UI、空卡片、过渡按钮、大鼠标、残字和半截界面。聚焦具体结果或有意义的真实动作，保留理解所需的完整视角；画面本身须有吸引力，不能仅靠钩子文字补救碎片、模糊或看不懂的素材，不靠虚假承诺或无关奇观截停观众。
- 声音和切点服务于这一真实悬念或反差，预先写明首句如何起、哪里停顿、现场声/音乐何时出现；不强制每秒切镜，不用音效掩盖内容空缺，不牺牲可懂度或连续操作。沿用已批准独立音乐开场时，明确前三秒为音乐钩子、不叠旁白，并同样安排真实核心画面；没有当前授权不擅改既有音乐规则。
- 写清后文用哪一段真实画面或信息兑现开头。素材尚未到位时可提出候选开头，但标为待验证，不说它已可制作或已证明能提高留存。

## 预稿最小交付与导出验收
- 预稿至少包含：一句具体切入点与观众信息差、0–3秒音画联合设计、大白话正文、逐段画面与素材状态、当前缺口。核验依据与素材权利另放后台记录，用户要审稿时优先让他看到故事本身。
- 写脚本或预稿不等于授权付费生成、数字人/声音克隆、发布或改动外部账号。只做预稿时不要自动制作整片，保留已有故事感封面、无自加角标、普通话口语和反向明暗原版片尾等规则。
- 实际导出后，将“首帧”和“0–3秒”分别验收：导出独立首帧图，按手机尺寸检查完整构图、清晰度与可读性；导出前三秒片段，逐帧检查并连续播放、实际试听音画钩子与节奏。不能仅靠编辑器预览、单图或抽帧推断整段合格，未导出/未试听就写未验收。
- 发布后若开头指标较差，先对照实际发布开头和平台指标，再提出一个优先测试。观察窗口、题材或样本不同的两条数据只提供线索，不能声称已证明某个开头造成差异；沿用发布后复盘的可比性、观察窗口和单变量测试要求。
