# Version-bound media continuation

This change uses the existing private Site, owner identity, app_state, production_reviews and production_stages. No migration, new table, public audience, credential, service or new paid authority is introduced. PixVerse approved V3 and the protected Claude job are unchanged until the owner acts.

The owner previews either read-only preparation or zero-new-fee private-video scope, then explicitly confirms it. Confirmation binds revision, approved draft SHA256, mode epoch and contract; it preserves script/source quality approval. Cancellation of a preview performs no write. Confirmation and withdrawal are immutable owner events with current-state CAS; same request and same current scope replay rather than queue additional probes. A new revision or mode invalidates scope. Active preparation/media leases refuse scope, mode and revision changes.

Two independent preparation stages enter the existing normal dispatch queue. One finite autonomous pass claims and probes both, stores exact technical results locally, then writes immutable Site receipts. Missing files, recordings, permissions, preview/timeline and Native Library handoff become actual blocked checks. No model call, audiovisual quality claim, fake ready manifest or media generation occurs in these probes. Each stage has a 10-minute lease and a maximum of three claims per script revision. Interrupted or blocked checks require an owner reason before a read-only retry; counters and historical receipts remain. Cached same receipts replay without further work.

License records are separate from scope, per original Library ID + byte SHA256, and record pending/denied/owner-documented status, actual evidence, rightsholder and exact uses. Generic consent is insufficient. Owner-documented records are explicitly not independent legal verification. Intake's original rights_pending status is retained. Formal cover/video/delivery gates require the current private-video scope plus the relevant documented uses. Existing media plans must bind media_scope_id; claims recheck it atomically. Scope does not skip prerequisite quality reviews, actual input SHA checks, zero-cost adapters or operation leases. The original native renderer/archive handoff still applies; this release does not pretend scheduled Node can upload to Library or understand a complete movie.
