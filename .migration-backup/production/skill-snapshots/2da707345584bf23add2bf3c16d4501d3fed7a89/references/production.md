# 制作规范

研究与预稿先执行 [素材先行的前置预稿](pre-draft.md)，把观众信息差、真实可用素材及0–3秒音画设计放在写正文之前。

## 画面和字幕
- **禁止自加技术角标。** 正式版和审阅版均不得自行烧入版本号、“审片”“本人声”、工具名、技术说明或调试标签；版本信息只放在文件名及交付说明中。未经用户明确要求，不额外添加任何角标或水印。原素材自带的版权/权利标记及已批准的品牌元素、品牌片尾须保留；不得借“去角标”删除来源水印。
- 所有竖版封面图采用3:4，不做9:16封面；封面比例与下述主片外画布分别处理。
- 外画布9:16：原型720×1280，发布可1080×1920同比放大。
- 720基准主画框3:4：x36、y160、宽648、高864，居中偏上；标题在上部。这是品牌主区布局，不是源素材必须裁满的窗口；外画布9:16、主区3:4、源片自身比例分别处理，以观众看懂内容为前提。
- 字幕置主框内底部约140px区域，默认约48px、至多两行，按语义断句。外画布底部256px作为平台安全区；核心信息不放这里。
- 横屏素材先保留原始完整视角，等比适配到3:4主区内；允许必要留白或沿用干净背景，不为填满主框默认中心裁切，更不拉伸。空间、路线、两端对象、坐标/刻度、数值、关键控件及动作与结果的关系必须可理解。水印处理必须符合素材来源权利与本次请求，过去某个项目的中心裁切许可不授权所有未来素材去水印。
- 本人开场、评论和结尾用3:4大画面。确需同时保留本人和素材时，使用真正圆形本人PIP，直径约148px，放左下或右下，避开主体、文字与字幕，禁止上下分屏；不要为了保留本人小窗压缩操作或细节证据。
- 选有意义的连续视频片段，不用短片重复循环凑时长。少用无意义两行文字卡，SI等必须解释的抽象概念才适当用卡。避免用冗长、单调、只复述口播提纲的大字静态卡撑时长；此类串讲可用数字人口播配底部字幕，具体沿用本片已批准选择，不把某片去掉提纲卡概括成所有信息卡禁用。

## 局部聚焦与开场画面
- 采用“全局建立 → 旁白对应的局部重点 → 回到全局”的镜头逻辑。先将完整横屏原片作为整体连续呈现，让观众知道正在看什么、对象在哪里以及彼此如何关联；不要从若干无上下文的局部碎片开始。全局段的停留由理解所需决定，不用一闪而过的全景充数。
- 旁白讲到具体操作或细节时，在同一连续源片上平滑移动聚焦、必要时适度放大，完整保留相关控件、动作与结果；重点讲完回到完整视角确认结果和整体关系。相邻重点之间也须让观众跟得上位置变化，不靠无依据跳切制造连续性；已有源片剪切不得冒充连续实录。没有局部强调需要时保持全局，不机械反复缩放，也不要默认加画中画。
- 放大以源分辨率和最终显示尺寸为限：记录源片真实尺寸、有效裁切区域、最终导出中该区域的显示尺寸，以及横纵像素放大倍数（显示尺寸÷对应有效源像素尺寸），把裁切、合成及最终导出放大一并计算。不能只读编辑器缩放百分比或用高清输出尺寸冒充高清素材。若文字糊、主体失真或关系丢失，减小放大、回到全局或寻找更清楚的原片；不以锐化、插值或继续放大掩盖信息不足。
- 不为填满3:4框牺牲空间、路线、数字及因果关系。需要看清数值时同时保留理解它所需的对象、单位、刻度或比较基准；若全局太小且局部又不能讲清，优先调整讲法、素材或镜头安排，必要时报告素材限制。裁切仍遵循来源权利与稳定性要求，不以放大掩盖缺失证据。
- 在这些段落，画中画只在确实必须同时保留全局与局部信息时选用；直接聚焦能讲清就不要再叠小窗。不把这一选择扩展为所有题材或所有画中画一律禁用。
- 第一帧单独看也须像完整成品，前三秒优先呈现清晰、有趣、真实的核心画面；去掉钩子文字后，真实动作、结果或反差本身仍须提供看点，不能用一句标题弥补裁碎、模糊或看不懂的画面；避开按钮过渡、大鼠标遮挡、残字和半截UI。选取真正合适的动态源片入点，不用截图、定格延长或重复帧凑“动态开场”。

## 实物短验证与稳定裁切
- 实物验证优先选一段短而完整的连续原片，保留关键动作和真实结果；统一该段画框比例与主体尺度，优先固定裁切窗口，不把验证剪成跳切、循环或重复片段。按上节先建立全局；跟随主体时以原片真实运动为依据，旁白确需强调细节时才按上节平滑聚焦并回全局，不能为“让画面动起来”额外平移或缩放。
- 先检查原片是否已有慢放、停顿或重复帧；源帧停住时不要让裁切窗口继续移动。避免将低更新频率的主体与持续变化的裁切位置叠加，造成新的人为跳动。不能把源片自带的顿挫误报为合成故障，也不能用进一步慢放或补帧掩盖未查明的问题。
- 对装水等实物演示，在相应操作后简短展示原片实际包含的验证，再快速回顾“遇到什么问题、改了哪里、怎样验证”。不为补齐叙事而编动作或扩大验证结论。旁白具体说发生的事，避免“杯子总算能当杯子”“装水还能端”等空泛、别扭的总结，也不套用为其他题材的固定台词。
- 时轴记录使用轻量模板：片段用途｜源文件、真实分辨率与入/出点｜源片速度/重帧情况｜全局/聚焦/回全局及对应旁白｜有效裁切区域、比例与必要关键帧｜最终显示尺寸与实际像素放大倍数｜旁白速度｜导出时间映射｜实际验证结果与QA状态。记录本项目真实值，不把某条片的倍速、时长或裁切坐标设为所有视频默认值。

## 正文口播：大白话讲故事
- 非接商单的兴趣故事内容，从观众被开头吸引的那个具体问题继续展开，重点讲真实效果、怎么玩或解决什么问题，并用实际画面佐证；结尾可落到与内容相关的互动问题或应用想法，不凭空追加平台推介。按素材和选题自然安排，不把这一方向套成每条同一套台词。
- 不让故事中途转为平台宣传、注册入口教学或地域、年龄、订阅条件清单；用户明确要教程/导购，或某项限制直接影响核心事实时才在正文说明。其他开放条件、核验依据和使用许可可放发布说明或素材记录，不机械塞进口播；仍须核验并准确表述，不能因省略条件而谎称人人立即可用、免费或无需限制。
- 游戏或交互演示题材，先展示实际存在的玩法、关卡或操作结果，再引入与之对应的文字修改等能力；逐一核对画面、游戏身份及修改前后关系。不得编造关卡、动作或改动结果，不用其他游戏或生成画面冒充同款实录，也不靠剪接让不同游戏看似同一游戏的修改前后。缺对应素材时调整说法或明确素材差异，不制造不存在的证据。
- 将“广告感可能影响推流”等考虑作为用户的内容取舍或待验证假设，不写成已证实的平台算法因果；不要以这一猜测替代可见数据和可比性核验。
- 把与封面、宣发相同的大白话和故事感要求覆盖到整段正文旁白。从具体人物或物件遇到的问题、出乎意料的反差、实际采取的行动及结果推进，让观众因为“接下来会怎样”继续听；再解释这件事与普通人的关系，不把背景知识清单当作故事。
- 少用技术名词、研究机构头衔和抽象总结，不以堆砌权威或“第一步/第二步/本课教你”的课程口吻撑时长。保留理解事实必需的来源和技术信息，用日常说法解释其具体作用；不为口语化改掉原意，也不强行把所有题材套成同一个叙事公式。
- 逐句区分已证实的现象、真实行动、实际结果和创作推断。不得为制造戏剧性补写失败、试验、动作、反应或效果。相近问题也不能偷换：例如“杯口封住”和“杯子漏水”是不同问题，未经来源证明不得互换。镜头没有展示、来源没有说明的步骤或测试结论，不写成亲眼所见或已验证事实。
- 封面、宣发和正文围绕同一真实切入点：正文兑现前两者引发的好奇，并给出新的具体信息，避免三处反复喊同一句生硬口号。轻讽刺应来自真实反差，不用夸张利害或虚构后果带节奏。
- 先用普通配音审阅全文和节奏，再使用本人声音生成正式口播的规则继续适用；明确的当前用户授权可按主流程覆盖。口语稿检查不止看词语是否简单，也要检查能否自然说出口、是否有具体事件推进，以及结论是否由事实支持。

## 故事感封面与宣发
- 所有封面必须偏故事感：用选题里具体的人、物件、动作或场景，呈现一个真实悬念、反差或尚未揭晓的结果，让人想知道“怎么回事/后来怎样”。不套用泛化科技海报，不靠抽象AI图标、技术名词堆砌或课堂式口号制造主题感。故事角度要由实际内容支持，不虚构人物经历、风险、冲突、结果或效果。
- 保持3:4竖版封面、上部标题和已有品牌风格；画面与短标题共同讲清一个具体切入点。手机尺寸核验主体、标题可辨认，避免文字遮住故事关键细节。保留已有获批版本，新的故事角度先交审阅。
- 整条视频制作时并行准备封面图及完整宣发包，随成片一起交付审阅，不等待另一次“做封面/写宣发”的请求。默认至少给出可直接使用的封面标题、发布标题、发布简介/正文和相关话题标签；本项目已约定的各渠道文案及相关宣发素材也一并完成。只做单段或局部修改时保留既有材料，只同步受影响部分，不擅自扩大任务。
- 标题和描述尽量大白话、短而具体，以读者愿意点进来为目标：从日常场景、意外发现、实际问题或可见反差切入，避免技术黑话、官方腔、过强的AI宣传味和“上课/教你”的教育定位。必要技术名词用普通话解释，不刻意隐藏内容真正的主题。
- 封面、标题和简介的悬念必须能由视频兑现；不编造利害关系，不靠虚假紧迫感、夸大承诺或无关噱头诱导点击。核对人物、物件、数字和事实与成片一致；留存用户实际批准的版本，审阅草稿不得提前标为定稿。
- 并行准备与一起交付不包含自动公开发布、付费生成、克隆声音/形象或新增分享权限；这些动作仍按当前授权执行。封面或宣发某一项受阻时说明缺项并继续其他工作，不让可独立完成的制作等待。

## 时轴、声音与音乐
- 音画共用编辑时轴；去静音要保尾字和语义转折。适度保音高提速且同步嘴型；所有修改后按实际词时间重对齐字幕。用户明确指定语速时，只对旁白音轨按该项目值保音高变速，按新词时间同步重对齐字幕、数字人口型和相关镜头切点；不对整片统一倍速。音乐开场、背景音乐及独立片尾保持自身速度，按新时轴重新摆放、剪接或淡入淡出；除非另有明确要求，不随旁白一起加速。
- 若用户要Suno歌词，写两段完整短歌词、非rap，有明显AI点题与调侃。不要自动购买、生成付费歌曲或发布。
- 用户上传歌曲后，挑约3秒抓耳hook作独立音乐开场，不叠旁白。总时长另加。背景优先选器乐段，低电平duck，不抢声，不硬循环。
- 无音频分离能力不能把含人声片段称为纯伴奏。封面暖场和结尾短促，不拖节奏。

## 可复核QA
1. 以ffprobe读源片与导出的视频/音频编码、时长、帧率、尺寸；以ffmpeg完整解码确认无损坏。逐段核对源分辨率、有效裁切区域、最终显示尺寸及实际像素放大倍数，在手机显示尺寸和导出原尺寸检查主体、控件和文字是否清楚；9:16外画布与3:4主区分别验收，比例合格不代表内容可懂。
2. 检查音频峰值、明显静音和音画长度。峰值通过不等于声音悦耳或可懂。
3. 首尾、切换、字幕最长行和主体运动关键帧以手机尺寸检查。逐帧检查实际导出文件的0–3秒，并连续播放复核：第一帧构图完整，核心画面可辨，无按钮过渡、大鼠标遮挡、残字、半截UI或伪动态；不能仅凭编辑器预览、单张截图或抽样关键帧宣称此项通过。字不得超安全区，圆形PIP不得压字/主体。逐段检查画面四角、所有叠加层和片尾，确认没有自加版本号、审片/本人声、工具或技术/调试标签及未获明确要求的角标/水印；审阅输出也必须检查，不能只查看首帧。发现此类标记先移除自加层、重新导出并复查，再交付可发布版本；保留原素材权利标记与已批准品牌元素。实物验证与疑似跳动处按源入/出点和变速映射，对照源片、导出相邻帧及实时播放，区分原片重帧/顿挫与裁切、缩放或合成新增的跳动；检查源帧停住时裁切窗口是否仍在移动。
4. 对照源片完整视角连续观看实际导出，确认先建立全局、随后局部重点有上下文、讲完回全局；观众能辨认对象、空间布局、路线起终点、数值及动作与结果关系，没有因裁切丢失信息或被切碎。逐句对照旁白核验聚焦对象、移动/放大开始与结束的时机，检查旁白说的内容是否当时可见、可读且属同一事实。前三秒另检查真实画面本身的吸引力，不把钩子文字合格当作画面合格。发现问题须修正并重新导出复查；素材不足须如实报告，不能只凭技术检查宣称通过。
5. 实际试听首句、快读句、每个剪点、音乐进出和片尾尾字；无法试听时明确只完成技术检查。
6. 保留旧版本、源媒体、逐段时轴和字幕词级时间，记录采用的来源与可用权利，不捏造已完成检查。

## 定稿交付与频道归档

沿用前述交付与QA要求，在用户批准项目最终版本后执行下列清单。只做脚本、局部审阅或尚未定稿时，保留工作成果并标明状态，不冒充完整定稿归档。

1. **核对定稿与范围。** 记录选题名、最终版本、定稿日期和用户批准来源；核对封面、成片和宣发材料对应同一版本。用户批准了视觉方向、一次渲染或某段修改，不代表已批准整片最终版本。缺少必备材料时明确缺项，继续准备可独立完成的部分，不把不完整归档标为完成。
2. **核对授权和接收方。** 用户工作流的路由线索是 Slack「语义引力」工作区（T0C713Z77PH）的「怎么用好ai视频号选题」频道（C0C7LSPS3U2）。执行时核实连接账号、实际工作区/频道、当前用户指令及仍适用的发送授权；以最新用户指令为准。技能中的路由记录本身不是发送许可，安装或调用此技能不授权替任何用户向该频道发送。仅在当前用户已授权定稿成果持续归档、且本次内容和接收方在其范围内时直接同步；否则先询问。不能访问时报告具体阻塞，不擅自改发别处、扩大受众或修改权限。
3. **齐备三件套。** 收集获批的3:4封面图、完整最终成片和完整宣发材料。宣发材料保留实际批准的标题、正文/简介、话题标签、各渠道文案及相关素材；未制作或未批准的部分标为缺失/待审，不编造为已完成。只发一段摘要、预览图或过期版本不能替代原件和完整文案。
4. **按项目成组留档。** 先查该项目是否已有归档消息，在一个项目主题/消息串中集中放置三件套及说明；没有时创建一组清楚标识选题和版本的归档。优先上传可直接打开的文件，或使用已验证频道成员可访问的链接；不要贴本地路径或私有下载地址充当交付。宣发正文较长时附完整文件。标明“已批准定稿”及版本/日期，把待审草稿明确分开。后续获批修订沿用该项目消息串，标注替代关系并保留旧版，不制造多个无法辨别的最终版。
5. **附简短收获或里程碑。** 有真实价值时写1–3条：本条视频形成的新想法、已收敛的制作方法、已完成并验证的技能改动或仍待测试的问题，并附相应版本、用户反馈、来源链接或观察日期。分别标注“观察”“假设”“已验证规则”；没有证据就说明待验证，没有有价值的新收获就略过，不能凑里程碑。涉及发布数据时读取 [发布后复盘](post-publish-review.md)，保留样本和可比性限制，不从一两条数据自动改写全局制作规则。技能改动只有实际保存并验证后才可写为已完成。
6. **核验发送结果。** 确认三件套发送成功、文件/链接可打开且对应正确版本，记录准确消息链接和缺项。发送结果不明确时先查频道，避免盲目重发造成重复；明确失败时只补失败部分。向用户简短回报归档结果和直达链接，未核验前不宣称已同步。

此流程限于已授权频道的定稿备案和日后分析。不要把归档当作视频号或其他平台公开发布授权；不要擅自补发历史项目、设置提醒/持续监测、扩大 Slack 受众或替用户接受新的分享权限。按当前请求保留历史版本与既有品牌、制作和发布后复盘规则。
